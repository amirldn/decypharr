# Rebase onto upstream v2.7.2 (2026-11-14)

The fork moved from upstream v2.6 (`3a0e0e2`) to v2.7.2 (`d6f8df0`, 29 Oct 2026). Each fork commit was
replayed in order (`0c1ee7c` and `0bbfcda` folded into one). The rule: where upstream had since shipped the
same fix, use upstream's code and keep the fork's tests; keep fork code only where it does more.

Previous deployed source: `d5d1710` (branch `feat/async-warm-add-timeout`).

## Fork behaviour kept over upstream

- **CDN URL resolution.** Upstream `8162e05` makes `fetchDownloadLink` call `requestdl?redirect=false`
  itself. The fork already resolves the URL once, lazily, through the budgeted `requestdl` resolver with
  priority lanes. With both, every link cost two `requestdl` calls (caught by
  `TestPlaybackRejectsBadRequestdlResponseWithoutCaching`). The fork's version stays;
  `TestFetchDownloadLinkDefersCDNResolution` replaces upstream's two tests for its lookup.
- **createtorrent hash check.** Upstream accepts any single entry. The fork rejects a lone entry whose hash
  is known and differs from the submitted one, and falls back to the magnet's hash when `InfoHash` is empty.
  The negative cache is evicted after a successful add.
- **TorBox status mapping.** The fork's case-insensitive list stays, with upstream's `queued` (#400) added.
- **Local downloads.** Upstream's cancellation context is threaded through; the fork's `DownloadLink`
  argument and background request class stay.

## Upstream behaviour now active

- `4d1793f` queue cleanup imports each download once; it sits alongside the fork's 15-minute grace and
  keep-partial-imports rules.
- `3f3d0fa` with `remove_stalled_after` set, Queued entries that are no longer waiting for a job worker are
  removed after the timeout (entries stuck in the "too many active downloads" retry loop).
- `c731217` post-download actions of deleted entries are cancelled. The fork's background pre-cache warm
  starts after completion and is not tied to that context; it reads at most 5 files with a 60s timeout.
- `26f9f51` Radarr manual-import payloads, `1945213` Prowlarr skipped in queue cleanup, `6cf99bb` repair of
  dangling Arr symlinks, `3de5d9e` Arr-file index skips files another Arr owns, `9be103c`, `8f378cd`,
  `7728467`, `b694475`, `e1712c0`.
- Hearsay peer blocklist (`917cfa2`): no effect while `hearsay.disabled` is true.
